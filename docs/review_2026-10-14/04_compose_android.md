# 04 Jetpack Compose and Android app quality (judged from source and the Compose compiler reports, 2026-10-14)

Scope: `app/src/main/java/com/example/blacksmithproject/` (all 62 Kotlin files read in part or whole), `app/src/debug/`,
`app/build.gradle.kts`, `gradle/libs.versions.toml`, both manifests, `res/values/themes.xml`. Compose compiler reports were
generated for the debug variant with the audit skill's init script (`app/build/compose_audit/`, not committed). Nothing was
run on a device; every "at font scale 2.0" line is from the code, marked hypothesis where a screenshot would settle it.
Typography, colour, the charter picker and the debug menu's look are in `05_ui_design.md` (findings 1, 2, 6, 7, 9, 18) and
are only cross-referenced here.

## Summary (10 lines)
1. Audit scores (skill `jetpack-compose-audit` 4.3.2, rubric in section D): Performance 7, State 7, Side effects 8, API quality 6, **overall 70/100**, confidence High. Strong Skipping is on; named-only skippability is 100 % (195/195), so no composable is structurally unskippable; the ceiling (8) comes from a handful of per-recomposition allocations, not from stability.
2. The architecture holds: every operation goes through `GameSession` under one mutex, the engine and JSON run on `Dispatchers.Default`, the Room commit is `NonCancellable` with a confirmation read, and the UI reads only the saved snapshot. Process death is covered (`SavedStateHandle` for dest/draft/sheet, the day cursor row for the shop day, `rememberSaveable` with semantic keys). No `collectAsState()`, every lazy list keyed, 18 of 18 collections lifecycle-aware.
3. Shipping gaps, not Compose gaps, rank highest: no baseline profile or `profileinstaller` (cold start of a Compose app without one is JIT-bound), no `ReportDrawnWhen`, and `screenOrientation="portrait"` under targetSdk 37 with no `android:appCategory="game"` (Android 16 ignores the lock on 600 dp+ screens unless the app is a game: verify).
4. "Whole workshop recomposes on every state tick": yes for the composables that take `UiState.Playing` (18) or the ViewModel (28), because every `edit {}` builds a new `Playing`; but their children receive the same `GameState`/`ShopUi` instances, so under Strong Skipping they skip, and there is no per-frame recomposition at that level. It is breadth, not cost; the fix is to stop passing `s` and `vm` wholesale.
5. The real per-frame work is in three leaves: `SiegeStage` and `MilestoneBurst` read an infinite transition in composition (the stage also re-resolves every actor bitmap per frame), and `WeaponSlot` feeds an animated `Dp` into `Modifier.padding`. All three are lambda-modifier or draw-phase fixes.
6. Settings flows (`reducedMotion`, `haptics`, `seenTips`) are collected straight from DataStore in five composables with `initialValue = false/ALL`, so a reduced-motion player gets animated first frames on every cold start, and TalkBack "exploring" is sampled once per screen entry.
7. Haptics: four of the six moments use `HapticFeedbackType` constants that only exist on API 30+ (`Confirm`, `Reject`) or 34+ (`SegmentTick`, `GestureThresholdActivate`); on minSdk 24-29 devices End Day, a refusal, a sale and the run's end are silent (hypothesis until run on an API 29 image). The forge haptic still fires when the dialog composes, not on the press (UI/UX review item 12, open).
8. Font scale 2.0: the destination bar is a fixed 72 dp with single-line, no-wrap labels (contradicting its own comment), seven `maxLines = 1` sites have no `overflow`, and PROGRESS already records the Shop lead under the fold. Elsewhere the code branches on `fontScale > 1.3` in 15 places, which is better than most apps.
9. Hypothesis worth a log line: End Day builds the shop-day script twice, because the snapshot is published while the session status is still `Working`, the status flips to `Idle` a moment later, and `mapLatest` cancels and restarts `scriptFor` whose cache is set only on completion.
10. Prior items: spinner first frame (UI/UX 0.7, cause 5) open; Gazette pill (cause 5) fixed; haptic on compose (cause 12) open; 48 dp / font 1.5 / TalkBack (thorough review 6) partly closed by `LayoutMatrixTest` and `ForgeResultCardTest` at 2.0, TalkBack still unautomated.

## C. Owner decisions
- Large screens: lock portrait by declaring the app a game (`appCategory="game"`, one line, also what Play expects), or accept landscape and budget a two-pane workshop. Trade-off: one line now versus a layout week later.
- Baseline profile: a Macrobenchmark module adds a device-run build step to the release runbook (minutes per release) for a measurably faster first launch on every install.
- Settings in `UiState`: the Loading state would also wait for DataStore's first read (single-digit ms) so reduced motion is right from frame one.
