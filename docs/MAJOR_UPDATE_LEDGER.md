# Major update ledger: tasks and evidence

Single source of truth for progress on `docs/MAJOR_UPDATE_PLAN.md`. One row per task; a row is only as true as its
evidence cell. Status words (restated 2026-10-10 so every row reads the same way):
- `done`: merged on `shop-day/m0` and checked at the level the task asks for. The bracket says where: `(emulator)` means
  somebody saw it run on the Android emulator, `(JVM)` or `(simulator)` means the task has no device step and its tests pass.
- `merged, device not run`: the code is on `shop-day/m0` and its JVM tests pass, but what it changes for the player was
  never run on an emulator or a phone in its merged form.
- `merged; device partial`: as above, and an agent saw part of it on the emulator, usually on its own tree before the merge.
- `partial`: part of the task is merged; the cell says which part is missing.
- `parked`: not started on the owner's instruction. `blocked`: waits for something outside the repository.
- `todo`: not on `shop-day/m0`. Where an agent has built it on its own branch the cell says so; that work is not in the build. `withdrawn`: dropped from the plan.
"Emulator" always means the Pixel_10_Pro virtual device on the development machine. No row was ever checked on a phone.
A session starts by reading this file and re-running the baseline commands of plan section 9.1, and ends by
updating it.

Baseline: release **v0.6.0**, `main` at `0ad888a` (balance v5, content v2, rules 1, schema 1).
